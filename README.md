## ANET 현재가가 `—$`로 나온 원인

### 진단

스크린샷을 보면 **데이터는 정상적으로 들어왔습니다.**

- `데이터 2014-06-06부터 3,063거래일` — ANET 상장일이 2014년 6월 6일이니 정확합니다
- `2026-08-11 종가 기준` — 날짜도 맞습니다

그런데 가격만 `—$`입니다. 앱의 `fmt()` 함수는 값이 NaN일 때 `—`를 반환하므로,
**마지막 행의 종가가 NaN**이라는 뜻입니다.

이것 하나로 화면 전체가 무너집니다.

| 화면 표시 | 실제 원인 |
|---|---|
| 현재가 `—$ —` | 마지막 종가 NaN |
| RS `—` | 수익률 계산에 NaN 전파 |
| 피봇 `189.66 (—)` | 피봇 대비 괴리율이 NaN |
| 매도 압력 `0/100` | 모든 비교 연산이 False |
| CANSLIM `35점` | N·L·S 항목이 전부 미충족 처리 |

**왜 NaN이 생기나** — yfinance와 Stooq는 장 시작 전이거나 데이터 반영이 지연되면
마지막 행을 자리만 만들어 두고 값을 비워서 줍니다. 이전 버전은 이 행을 그대로 썼습니다.

### 수정

**① `clean_ohlcv()` 정리 단계를 모든 시세에 강제 적용**

시세를 받으면 반드시 이 함수를 통과시킵니다.

- 종가가 비었거나 0인 행 **제거** ← 이번 문제의 직접 해결
- 멀티인덱스 컬럼 평탄화 (`yf.download` 단일 티커)
- 컬럼명 표준화 (`시가/고가/저가/종가/거래량`, `Adj Close` 포함)
- 문자열로 온 숫자를 강제 변환
- 타임존 제거, 중복 날짜 정리, 날짜순 정렬
- OHLC 결측은 종가로 보정, 거래량 결측은 0

**② 소스 캐스케이드 — 실패하면 다음 소스로**

정리 후에도 유효 종가가 없으면 다음 소스로 넘어갑니다.

| 시장 | 순서 |
|---|---|
| 해외 | yfinance history → yfinance download → yfinance 10y → FinanceDataReader(Stooq) |
| 국내 | FinanceDataReader → pykrx → yfinance `.KS` → yfinance `.KQ` |

**③ 최종 관문**

`build_context`에서 마지막 종가가 유효하지 않으면 분석을 진행하지 않고
"현재가가 유효하지 않습니다"를 명시적으로 표시합니다. `—`로 조용히 넘어가지 않습니다.

**④ 지수에도 동일 적용**

다우·S&P·나스닥·코스피·코스닥도 같은 정리를 거칩니다.
거래량이 없는 지수는 "거래량 없음(분산일 판정 제한)"으로 로그에 남깁니다.

**⑤ 진단 강화**

- 성공 로그에 `소스 · 기간 · 최종 종가`를 함께 남깁니다
  (예: `yfinance history · 3,063일 (2014-06-06 ~ 2026-08-11) · 최종 종가 189.66`)
- 개별종목 탭 "종목 정보 검증" 안에 **최근 시세 5행 원본**을 볼 수 있는 항목을 추가했습니다

### 검증

실패 유형을 모두 만들어 통과 여부를 확인했습니다.

| 입력 상태 | 결과 |
|---|---|
| 마지막 행 전체 NaN (이번 증상) | 199행, 종가 165.43 · "결측 1건 제거" |
| 마지막 3행 + 중간 결측 | 196행, 정상 |
| 마지막 종가 0 | 198행, 정상 |
| 멀티인덱스 컬럼 | 평탄화 후 정상 |
| 종가가 문자열 | 숫자 변환 후 정상 |
| `Adj Close`만 존재 | Close로 대체 후 정상 |
| 한글 컬럼 (pykrx) | 표준화 후 정상 |
| 거래량 컬럼 없음 | 정상 (지수용) |
| tz-aware 인덱스 | 정상 |
| Close 컬럼 없음 / 전부 NaN / 빈 프레임 | **None 반환** → 다음 소스로 |
